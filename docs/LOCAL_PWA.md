# Локальная PWA GYM

GYM собирается как статический PWA для GitHub Pages и устанавливается на главный экран iPhone.
Тренировки и настройки хранятся в `localStorage` телефона, собственные фото и видео — в IndexedDB.
В настройках приложения можно сохранить резервную копию JSON или ZIP с медиа и восстановить её
на этом же или другом устройстве.

## Установка на iPhone

Откройте адрес Pages в Safari, дождитесь первого запуска и выберите «Поделиться» → «На экран
Домой». Открывайте GYM с этого значка. Для установки и service worker нужен HTTPS; GitHub Pages
его предоставляет. При очистке данных сайта или нехватке места iOS может удалить локальное
хранилище, поэтому регулярно скачивайте резервную копию и храните её отдельно.

## Примерный расход и Apple Health

После завершённой силовой тренировки карточка **«Примерный расход»** появляется в итоговом экране и
в истории. Расчёт выполняется на телефоне по всей длительности сессии, включая паузы. Формула:

```text
active = (MET - 1) × 3.5 × bodyweightKg / 200 × minutes
```

Используются три заранее выбранных уровня: `light = 3.0`, `moderate = 3.5` (по умолчанию),
`vigorous = 6.0`. Калорийные величины округляются до 10 ккал. Это условная оценка, а не измерение:
вес снаряда и `kg × reps` не становятся множителем, сложного classifier-а упражнений нет, чистые кардио-
записи не оцениваются. Если вес не найден, GYM предлагает ввести его. Приоритет такой: настройка для
этой тренировки, `w.bw` сессии, сохранённый общий вес, затем последний weigh-in до даты тренировки.
Новый weigh-in при этом не создаётся. Настройки оценки и локальный ledger передачи сохраняются в
`localEnergy`/`localHealth` и попадают в обычный JSON/ZIP backup.

### Установка команды

Установку нужно сделать один раз на iPhone или iPad:

1. В GYM нажмите **«Добавить в Здоровье»**, затем откройте [актуальный v2-файл
   `GYM-Health.shortcut`](https://if911.github.io/GYM/shortcuts/v2/GYM-Health.shortcut).
2. Если Safari скачал файл, откройте его в приложении **«Файлы»** и добавьте команду с именем
   **`GYM-Health`**.
3. Вернитесь в GYM с иконки приложения на экране «Домой» и нажмите **«Я добавил команду»**.
4. При первой записи разрешите «Командам» добавлять тренировки в «Здоровье».

Для уже установленной команды `GYM-Health` сначала удалите или замените только старую команду в
приложении «Команды», затем установите v2 с тем же именем. Старый root URL обновляется алиасом, но
Safari может держать его в кэше, поэтому используйте именно `/shortcuts/v2/GYM-Health.shortcut`.
Данные GYM и Safari для переустановки очищать не нужно.
Флаг установленной команды теперь включает `shortcutRevision: 2`. Прежняя отметка без версии
предлагает заменить команду. В recovery flow кнопка повторной отправки недоступна, пока пользователь
не нажмёт «Я добавил команду»; эта отметка не запускает передачу и сохраняет pending ledger.

После этого **«Добавить в Здоровье»** доступна после завершения тренировки и в истории. GYM передаёт
команде только JSON с `version`, идентификатором передачи `id`, `start`, `end`, `minutes` и `activeKcal`. В payload
нет упражнений и заметок; HTTP-запросы, callback URL и clipboard не используются. Запуск идёт
через Apple Shortcuts URL scheme. Apple описывает формат запуска `shortcuts://run-shortcut?...&input=text&text=...`
в [официальной инструкции Shortcuts](https://support.apple.com/en-au/guide/shortcuts/apd624386f42/ios).

Открытие команды не подтверждает запись в Health. До запуска GYM сохраняет на телефоне ledger со статусом
`pending`; после проверки пользователем нажимается **«Тренировка есть в Здоровье»**, и только тогда
статус становится `confirmed`. При проблеме есть **«Не добавилось — повторить»**: после предупреждения
о возможном дубликате marker заменяется новым pending в одном сохранении, затем запускается команда.
При ошибке сохранения прежняя запись в хранилище остаётся, новая передача не запускается. Автоматического retry
при возвращении в приложение нет. Apple Health и возможная синхронизация через iCloud остаются выбором
владельца устройства и не являются облачной отправкой GYM.
Команда показывает подтверждение с кнопкой отмены перед каждой записью. Если тренировку уже записали
часы или другое приложение, отмените передачу во избежание дубля. Изменение или удаление тренировки
в GYM не редактирует и не удаляет созданную запись в «Здоровье»; её можно изменить в самом «Здоровье».

### Artifact и проверка

`frontend/public/GYM-Health.shortcut.plist` — детерминированный источник команды, а
`frontend/public/GYM-Health.shortcut` — подписанный generic artifact. Builder использует штатный macOS
`shortcuts sign --mode anyone`; в `GYM-Health.integrity.json` фиксируются SHA-256 source и signed файла.
Подпись через Apple получает только общий код команды, без тренировочных данных.
Проверка воспроизводимости, цепочки Health action, запрета network/clipboard/iCloud actions и соответствия
динамических полей выполняется так:

```sh
python3 scripts/build-health-shortcut.test.py
```

Пересобрать источник и подписанный файл на macOS можно так:

```sh
python3 scripts/build-health-shortcut.py
```

v2 исправляет формат вложенных переменных чисел (прямой `ActionOutput` вместо неподдержанного вложенного
attachment) и inline token строки даты. Прежние пять структурных тестов не могли обнаружить эту runtime-
несовместимость. Теперь в наборе семь тестов, включая две новые регрессии на формат числовых ссылок
и даты: обе падали на старом artifact-е и проходят после исправления. Числовой контракт сверяется с
[сериализатором Cherri](https://github.com/electrikmilk/cherri/blob/main/action.go), поле даты — с
[экспортом date field](https://gist.github.com/aont/c182357d1dad0f6ca2932a54654aa3c1) и metadata
`WFDateFieldParameter`. Это проверка формата, а не запуск Apple runtime. CLI-подпись успешна, SHA
совпадает с integrity JSON. Доступ к native редактору Mac не разрешён; фактическая запись исправленной
команды на iPhone ещё требует проверки. Локальная проверка структуры не подтверждает запись в Health.

Публичная Pages-сборка содержит только приложение, каталог и лицензированные 180 px media.
Она не содержит тренировочные записи. Service worker кэширует статические ресурсы и не кэширует
API и внешние адреса. API и запросы записи блокируются до отправки; web push отключён.

Русский — язык по умолчанию этой сборки. При первом запуске исправленного выпуска старый
английский профиль один раз переходит на русский. Новые RU preferences по умолчанию показывают
русские названия без английских скобок; уже настроенные предпочтения названий сохраняются.
Меняются только предпочтения отображения. Маркер `gym_ru_default_v1` на этом устройстве
позволяет затем осознанно выбрать другой язык без повторного сброса при запуске.
После выпуска открыть GYM с интернетом, дать загрузиться обновлению, закрыть и открыть снова.
Удалять приложение или данные Safari для обновления не требуется.

## Личная программа по ссылке

В разделе «План» есть отдельная видимая кнопка **«Добавить программу по ссылке»** над
переключателем «Расписание / Программы». Она открывает поле **«Ссылка на программу»**
и поле отдельного кода. На iPhone зажать поле ссылки и выбрать «Вставить».
Открывать этот экран внутри установленного GYM, чтобы использовать
тот же дневник. Прямая ссылка `#/import-plan/<payload>` тоже открывает форму и сразу заменяет
текущий адрес на `#/import-plan`; payload остаётся только в памяти до выхода или reload.
До подтверждения стандартного preview дневник не меняется. Импорт добавляет новые программы;
расписание заменяется только по отдельному переключателю в preview.

Формат v1: gzip JSON → AES-GCM 256, случайные 16-byte salt и 12-byte IV, ключ из отдельного
пароля PBKDF2 SHA-256 (210000 iterations). Пароля/ключа в URL нет. Payload — base64url в fragment;
HTTP не передаёт fragment серверу. Никакого хранилища ссылок/планов на Pages или стороннем
сервисе нет. Ограничения: 64 KiB payload, 512 KiB распакованных данных, отказ от опасных ключей
и чрезмерной вложенности. После decrypt используется штатный `parsePlan` с конвертацией единиц.
Неверный код, повреждённая ссылка и неверный формат показывают общее сообщение без содержимого.

Личную ссылку и код создавать/хранить вне Git. Вместе они дают доступ к программе, в том числе
человеку с доступом к переписке. Fragment может сохраняться в чатах, буфере и истории браузера;
удаление из текущего адреса не удаляет эти копии. На сервер не отправляется программа, но
при загрузке оболочки GitHub по-прежнему видит обычные статические запросы и IP.
Функция не меняет формат дневника, не содержит истории тренировок и не заменяет JSON/ZIP backup.
WebCrypto требует HTTPS, Compression Streams доступны в современных Safari (iOS 16.4+).
Поддержка без этих API не эмулируется: показано сообщение, остаётся импорт файла.

## Блины и оценка максимума

`lib/exercise-tools.js` определяет видимость инструментов по категории, оборудованию,
режиму записи и выбранному способу нагрузки. Изменение касается отображения: старые записи,
веса, настройки оборудования и исходные расчёты не переписываются.

- Прыжки, удержания, кардио, растяжка, mobility/yoga/pilates, rehab и combat не показывают
  эти инструменты, в том числе при старом ошибочном override блинов.
- Подбор блинов доступен для штанг/Smith, нагружаемых блинами саней и другого подходящего
  оборудования. У гантелей, гирь, резинок и кабельных тренажёров он скрыт.
- Каталог не различает все блочные и нагружаемые блинами рычажные тренажёры. По умолчанию
  подбор на них скрыт. В настройках упражнения кнопка «Этот тренажёр с блинами» позволяет
  явно включить его; старый выбор оборудования сохраняется, включая legacy string формат.
- Калькулятор максимума на один повтор показывается для подходящей силовой работы с нагрузкой.
  Без истории поля пустые, пример «20 кг × 5» не подставляется. Для неподходящей работы оценка
  также скрыта в истории, статистике и итоговом сообщении о рекорде.

Русские подписи объясняют, что считается: «Подбор блинов», «Вес грифа», «Вес без блинов»,
«Все вместе»; максимум назван «Оценка максимума на 1 повтор». Вес без блинов означает
указанный вес пустой подвижной части или саней, а не массу всей рамы тренажёра.

## Резервная копия и исходники

Кнопки экспорта и импорта находятся в Settings. JSON-файл содержит пользовательские данные — не
публикуйте его и не прикладывайте к issue. `source.tar.gz` в каждой сборке — исходники текущего
коммита под AGPL-3.0-or-later без секретов, runtime, `node_modules`, native shells и бинарных
media. Лицензированные media восстанавливаются отдельно из каталога `catalogue/media` ровно из
upstream commit `e348fc17`; файл `catalogue/media/NOTICE.md` обязателен.
`LICENSE` и `NOTICE.md` также опубликованы рядом с приложением; ссылка на уведомления не зависит
от сайта или будущих изменений исходного проекта.

## GitHub Pages

### Обновление установленного приложения

`lib/local-pwa-update.js` регистрирует local worker с `updateViaCache: none` и проверяет его
на старте, при focus, online и возвращении видимой страницы. Автоматические проверки ограничены
одной в минуту; ручная кнопка в «О приложении и обновления» обходит этот интервал и ждёт установки.
Worker сообщает через MessageChannel только URL entry module и stylesheet из своего уже установленного shell.
Сравнение с текущим документом отличает обновление кода или CSS от первого `clients.claim()`.
Пока URL различаются, баннер предлагает явный reload; автоматического reload/navigate нет.
Несохранённый ввод сохраняется до нажатия. Сохранённая активная тренировка восстанавливается.
Ни хранилище дневника, ни форматы backup этот механизм не меняет и данные из них не читает.

Навигация остаётся cache-first: все файлы нового shell должны успешно установиться до активации,
чтобы следующий запуск офлайн не получил новый HTML без необходимых ему JS/locale файлов.
Старая версия без updater listener требует одного настоящего перезапуска после загрузки worker.
На iPhone закрыть именно карточку GYM в переключателе приложений, затем открыть с иконки с сетью.
Не удалять приложение и не очищать данные Safari для обновления.

Workflow `.github/workflows/local-pwa.yml` выполняет `npm ci`, тесты, проверки locale, `npm run
build:local`, затем публикует `frontend/dist` через встроенный `GITHUB_TOKEN`. Один раз включите
Settings → Pages → Source: GitHub Actions. Для бесплатной публикации используется публичный
`IF911/GYM`: код и материалы доступны всем, дневник каждого пользователя остаётся на его
устройстве. Сборка запускается на push в `main` и вручную из Actions.

## Проверка зависимостей перед публикацией

`npm run check:security` проверяет полный npm audit, включая dev dependencies,
и совместимость native tooling на временных искусственных файлах. Обе проверки
обязательны в Pages и upstream validation. Причины overrides и точные команды —
в [DEPENDENCY_SECURITY.md](DEPENDENCY_SECURITY.md). Они не меняют формат и адрес
хранилища GYM, русские тексты или установленную команду Health.

## Автоматическое обновление upstream

Отдельный workflow `upstream-sync.yml` проверяет upstream ежедневно в 02:17 UTC (05:17 Москва).
`prepare` без прав записи делает обычный merge, сохраняя локальные коммиты. При конфликте
или изменении защищённого кода он не заменяет файлы версией автора, а останавливается.
`validate` без прав записи строит предыдущую и новую версии, выполняет полный frontend suite,
locale/fatigue checks и browser smoke на одном origin: тренировка, программы, вес, custom exercise,
IndexedDB media, JSON export, офлайн-запуск и восстановление backup должны сохраниться.

Только отдельный `promote` с правами записи проверяет SHA и родителей проверенного merge,
убеждается, что main не изменился, и выполняет обычный fast-forward push. Код candidate в этом
job не запускается. Он явно вызывает `workflow_dispatch` штатного Pages workflow с ожидаемым SHA:
обычный push через `GITHUB_TOKEN` сам по себе новый workflow не запускает. Pages повторно проверяет
этот commit и публикует после успешной сборки. Новый PAT или SSH-ключ для автоматизации не нужен.

Неоднозначные обновления хранилища, backup, local guards, workflow и лицензий требуют ручного
совмещения. Ручная база от 2026-10-24 — openGym 1.4.2 (`7a3ace53`).
При объединении backup без аккаунта новые и текущие тренировки объединяются; поля GYM
`localEnergy` и `localHealth` сохраняются и при импорте старой копии без этих полей.
Настройки калорий из backup имеют приоритет; текущие отметки отправки в Health имеют
приоритет при совпадении id, чтобы старая копия не откатывала защиту от повторной передачи.
Native iOS/Watch workflow upstream ограничен repository автора и в GYM не выполняется. Пакетные версии могут обновляться, но команды обязательных проверок закреплены.
Один GitHub issue сообщает о блокировке без повторных одинаковых сообщений. При ошибке после
push main уже может содержать обновление, поэтому состояние сайта проверяется по Pages run.
Сбой deploy виден в штатном Pages workflow и уведомлениях GitHub; автоматического revert нет.
Данные телефона не покидают устройство, а JSON/ZIP backup по-прежнему рекомендуется сохранять
регулярно: тесты не гарантируют совместимость любого будущего обновления со всеми дневниками.

При проблеме выполните `git revert` для проблемного commit в `main` и отправьте новый commit; старый cache
service worker удаляется только после успешной установки нового shell. Откат Pages не восстанавливает
удалённые данные Safari, поэтому сначала используйте JSON backup.
